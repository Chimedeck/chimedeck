## Update
- `fetchNotificationsThunk.fulfilled` reducer now **merges** new items into the existing list instead of replacing it, so polling refreshes (30s interval, tab focus, WS reconnect) no longer wipe pages accumulated via "Load more".
- Cursor and `hasMore` are now only seeded on initial load (`cursor === null`), preventing polling refreshes from resetting pagination state and causing subsequent "Load more" clicks to silently re-fetch already-loaded pages.
