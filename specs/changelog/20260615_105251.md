## Update
- **Session-scoped board chat.** Replaced the single-thread-per-board model with multiple chat sessions (threads). Users must explicitly create or select a session before chatting, preventing token overload from one monolithic history.
- `board_chat_threads` now supports multiple rows per `board_id` — the UNIQUE constraint on `board_id` was removed and replaced with a composite index on `[board_id, last_message_at]` for fast session listing.
- Added `name` and `created_by` columns to `board_chat_threads` for session metadata.
- All chat APIs (`POST/GET /chat/messages`, `POST /chat/assist`) now require `sessionId` — requests without it return 400 with a clear error message instructing the user to create a session first.
- New session management API: `GET/POST /chat/sessions`, `GET/PATCH /chat/sessions/:sessionId`.
- Chat history is now session-scoped: `GET /chat/messages` accepts optional `sessionId` query param; when absent, returns all messages (for backward compatibility with any non-UI consumers). The frontend always passes `sessionId`.
- AI assist context is scoped to the active session — message context for LLM calls is filtered by `thread_id`.
- Frontend `BoardChatDrawer` now shows a session selector dropdown + "New" button above the history area. Sessions are **auto-created** on the first message — the input box is always enabled and a session is transparently created when the user sends their first message. Users can switch between existing sessions via the dropdown.

## New
- `server/extensions/board/mods/chat/sessions/index.ts` — session CRUD module (create, list, get, update).
- `server/extensions/board/api/chatSessions/index.ts` — session API route handlers.
- `db/migrations/20260615_board_chat_multi_session.ts` — migration to drop the UNIQUE constraint, add `name`/`created_by` columns, and add the composite index.

## Technical Debt
- Existing boards with one monolithic thread will have that thread persisted — users can continue using it by selecting it from the dropdown, or start fresh with new sessions.
- The `chat/search` endpoint (semantic vector search) still searches across all messages regardless of session — not yet session-scoped.
- `GET /chat/messages` without `sessionId` still returns all board messages; consider deprecating session-less queries in a future sprint.
