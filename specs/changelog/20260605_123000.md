## Update
- Added a GitHub App webhook receiver at `POST /api/v1/github/webhook`. Until now we only *read* from GitHub via the App's installation token — there was no place for GitHub to push events back to us. The new endpoint verifies the `X-Hub-Signature-256` HMAC, then dispatches by `X-GitHub-Event` to a per-installation handler.
- Signature verification rejects with 401 in all environments when the signature is missing, malformed, or doesn't match. Two candidate secrets are tried, in order: (1) the per-installation secret stored in `github_app_installations.webhook_secret_encrypted` (decrypted with `WEBHOOK_SECRET_ENCRYPTION_KEY`), (2) the `GITHUB_APP_WEBHOOK_SECRET` env fallback. The fallback exists so the very first `installation.created` event can be verified before we have anything in the DB.
- Implemented event handlers (idempotent): `installation` (upsert / delete / suspend / unsuspend), `installation_repositories` (merge added + remove removed into the cached repo list), `push` (currently a no-op; cache-invalidation hook is wired and ready for the next iteration). All other event types are acknowledged with 202 and otherwise ignored.

## New
- Added migration `0123_github_app_installations` — `github_app_installations` table (PK `installation_id`, `account_login`, `account_type`, nullable `workspace_id` FK, `repositories` JSONB, `suspended`, encrypted `webhook_secret_encrypted`).
- Added `server/extensions/githubApp/`:
  - `mods/verifySignature.ts` — HMAC-SHA256 + `timingSafeEqual` verifier with two-candidate-secret support.
  - `mods/installations.ts` — DB layer (`getInstallationById`, `getInstallationWebhookSecret`, `upsertInstallation`, `deleteInstallation`).
  - `mods/dispatch.ts` — `dispatchGitHubEvent` router + per-event handlers.
  - `api/webhook.ts` — route handler: env gate → method check → raw body → candidate-secret resolution → signature verify → dispatch → 202.
  - `api/index.ts` — thin router mounted at `/api/v1/github/webhook`.
- Added env vars `GITHUB_WEBHOOKS_ENABLED` (gate) and `GITHUB_APP_WEBHOOK_SECRET` (HMAC fallback). Default off in local dev.
- Mounted the new router in `server/index.ts` (right after the existing webhooks router).
- Added tests: 10 in `__tests__/verifySignature.test.ts`, 11 in `__tests__/webhook.test.ts`. All 21 pass.

## Technical Debt
- The `push` handler is intentionally a no-op for now — the installation row is persisted, but the actual cache-invalidation in `GITHUB_REPOSITORY_CACHE_DIR/<full_name>` needs a helper that doesn't exist yet. Wiring the call site will be a 1-line change in `handlePush`.
- The very first `installation.created` event signs with a secret that has to match `GITHUB_APP_WEBHOOK_SECRET`. There's currently no UI for the operator to set a different secret per-installation — the per-installation column is a write-through cache of the same value. If we later need per-installation rotation, we'll need a small API + admin UI to set it without going through GitHub's webhook redelivery.

## What Should Be Done Next
- Wire the existing `GITHUB_REPOSITORY_CACHE_DIR` cache into the `push` handler so board-docs refresh automatically on commit.
- Add a `GET /api/v1/github/installations` endpoint + sidebar entry for workspace admins to see the installation list and link it to a workspace.
- Add a `pull_request` handler that posts a comment on the linked card when a PR is opened against a branch matching the card.
- Consider rate-limiting the receiver (currently each GitHub delivery costs us a DB write + decrypt).
