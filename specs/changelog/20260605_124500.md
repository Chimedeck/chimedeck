## Update
- The board-chat *embedding* path is now independently controllable via the `CHAT_EMBEDDING_ENABLED` flag (default `true`). When set to `false`, `getEmbeddingProviderConfig()` throws `chat-embedding-feature-disabled` instead of `chat-embedding-provider-not-configured`, so the UI can render a clear "vector search is off" message rather than a confusing "not configured" error.
- Motivated by Ollama Cloud, which currently exposes chat models but no `/v1/embeddings` endpoint. Operators on Ollama Cloud can now run with `CHAT_PROVIDER=ollama` + `CHAT_EMBEDDING_ENABLED=false` and use chat features without the vector path spamming errors on every write.

## New
- Added `CHAT_EMBEDDING_ENABLED` env var (default `true`). Wired into the resolver as the very first check so a disabled flag overrides any provider configuration.
- Added `chatEmbeddingEnabled` to the `/api/v1/flags` response, the Redux `featureFlagsSlice` state, and a new `selectChatEmbeddingEnabled` selector. Independent of `boardChatEnabled` — chat can stay on while semantic retrieval is off.
- Added three new resolver tests covering the feature-disabled path: `CHAT_EMBEDDING_ENABLED=false` short-circuits both the OpenAI and Ollama branches; any value other than the literal string `'false'` keeps the embedding path enabled (matches `env.ts` semantics).
- Updated `.env.example` with the new flag and a short note pointing operators at the Ollama Cloud use case.

## Technical Debt
- The resolver throws a plain `Error` with a string message. No call site in the codebase currently pattern-matches on the error name, so this is forward-looking — when the chat-write path gains a more specific error class, `chat-embedding-feature-disabled` should become a typed error alongside `chat-embedding-provider-not-configured`.
- `selectChatEmbeddingEnabled` is exported but no client component consumes it yet. The plan is to gate the "vector search" affordance in the chat UI on this flag so users on Ollama Cloud see a disabled button instead of a silent failure.

## What Should Be Done Next
- Add a `usePlanGate`-style hook or direct selector wiring in the board chat UI to show a "Semantic search is disabled" badge when `chatEmbeddingEnabled` is false.
- Surface the new flag in any operator-facing health check or admin dashboard so it's discoverable from the running app.
- Consider applying the same `*-enabled` gate pattern to the assist path (`CHAT_ASSIST_ENABLED`) for deployments that want a chat-but-no-AI mode.
