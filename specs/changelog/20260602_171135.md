# Changelog

## Update

- Fixed Stripe Checkout and Billing Portal return URL construction for development and reverse-proxy setups.
- Return URLs now prefer request `Origin`/`Referer` (frontend origin, e.g. `http://localhost:5173`) instead of always using `APP_URL`.
- This prevents checkout success/cancel redirects from incorrectly sending users to the backend port (`:3000`) during local development.

## New

- Added integration test coverage for checkout session URL generation to verify `success_url` and `cancel_url` use request origin.
- Added integration test coverage for billing portal `return_url` using request origin.

## Technical Debt

- Checkout and portal modules currently duplicate origin-resolution helper logic; this can be centralized in a shared subscription URL utility.

## What Should Be Done Next

- Optionally centralize app-origin resolution into a shared helper used by all server-generated frontend links.
- Add one browser-level Playwright test to verify a full checkout success redirect lands on the active frontend host in local development.
