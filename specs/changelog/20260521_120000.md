## Update
- Added state-transition coverage to CLI and MCP interfaces so the same board transition workflows exposed in REST/OpenAPI are accessible through automation channels.
- Wired new command/tool registration paths so they are available by default without extra flags.

## New
- CLI commands:
  - `get-state-transitions` -> `GET /api/v1/boards/:boardId/state-transitions`
  - `set-state-transitions` -> `PUT /api/v1/boards/:boardId/state-transitions`
  - `get-state-transition-rules` -> `GET /api/v1/boards/:boardId/state-transitions/rules`
  - `copy-state-transitions` -> `POST /api/v1/boards/:boardId/state-transitions/copy`
- MCP tools:
  - `get_state_transitions`
  - `set_state_transitions`
  - `get_state_transition_rules`
  - `copy_state_transitions`
- Documentation updates in CLI and MCP READMEs for new commands/tools and parameters.
- In-app docs updates:
  - Refreshed MCP docs page with the 4 new state-transition tools and parameter tables.
  - Added a new CLI docs page at `/developer/cli` and wired sidebar navigation.

## Technical Debt
- CLI graph payload input currently validates only that parsed JSON is an object; deeper shape validation still relies on server-side validation.
- MCP tool responses currently return serialized JSON text blocks for consistency with existing tools; structured content responses could improve downstream tooling ergonomics.
