## Update
- Fixed wrapped link destination normalization in card description markdown so browser-native "Open Link in New Tab" uses the real URL instead of an encoded markdown token path.

## New
- `normalizeMarkdownLinkUrls` now unwraps markdown-form destinations (including percent-encoded variants) when they appear in the link destination slot.
- Example fixed shape: `]([ChimeDeck](http://...))` now normalizes to `](http://...)`.

## Technical Debt
- Similar nested-markdown destination sanitization may be needed in other markdown normalizers if additional surfaces can persist malformed link destinations.

## What Should Be Done Next
- Add regression tests for markdown link destination normalization with nested markdown tokens and encoded token variants.
