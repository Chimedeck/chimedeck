## New
- **DB migrations**: `20260611_card_sprint_generation_runs.ts` (tracks generation jobs with status, tier, snapshot FK, output file paths, trigger run FK) and `20260611_generated_sprint_cards.ts` (links child sprint cards to originating feature card and generation run). Column types corrected to `string(255)` for `created_by`, `workspace_id`, and `card_id` to match the existing MongoDB-style hex IDs.
- **Sprint generation extension** (`server/extensions/sprintGeneration/`): Full implementation following the established `api/` + `mods/` + `common/config/` + `types.ts` pattern.
  - **Config**: Feature flag key `SPRINT_GENERATION_ENABLED`, tier quota limits (`tier_1: 1`, `tier_2: 3`, `tier_3: 6`, `tier_4: Infinity`), allowed output paths (`specs/sprints/`, `specs/request_changelog/`), max retry attempts.
  - **API router**: Matches `POST /api/v1/cards/:cardId/sprint/generate` — gated by feature flag, resolves card via `resolveCardId`, enforces board visibility, delegates to handler.
  - **Generate handler**: Authenticates via `req.currentUser`, validates workspace membership, queries card metadata (title, description, workspace_id via list→board join), creates sprint generation run in `QUEUED` status, invokes pipeline asynchronously.
  - **Pipeline orchestrator** (`mods/pipeline/index.ts`): Composes readRequirements → generateArtifacts → createSprintCards. Advances run status through `QUEUED → RUNNING → SUCCEEDED/FAILED`. Handles idempotency checks for existing `SUCCEEDED` runs.
  - **Read requirements** (`mods/pipeline/readRequirements.ts`): Cross-extension data access — reads refined requirement packet from `card_chat_messages` (for `READY_FOR_REVIEW` sessions) and context snapshot from `card_ai_context_snapshots`.
  - **Generate artifacts** (`mods/pipeline/generateArtifacts.ts`): Generates sprint spec files (`specs/sprints/sprint-plan.md` update, `specs/sprints/sprint-<n>.md` with EARS requirements + AC + dependencies + test sections), creates/updates request changelog entries. Reuses board-chat provider config pattern for AI completion calls. Tier-aware output: tier_3+ gets dependency graph, tier_4 gets test matrix + risk register.
  - **Create sprint cards** (`mods/pipeline/createSprintCards.ts`): Creates child sprint cards in board with trace links to spec files and originating feature card. Determines sprint number by incrementing max existing + 1. Places cards in the board's first list.
  - **Tier policy** (`mods/tierPolicy/`): Resolution (`index.ts`) determines feature availability per tier (dependency graph ≥ tier_3, test matrix / risk register = tier_4). Quota enforcer (`quotaEnforcer.ts`) truncates sprint count to tier max, flags over-limit sprints as `SKIPPED`, emits `sprint_generation_quota_exceeded` activity event.
  - **Activities** (`mods/activities/index.ts`): Fire-and-forget dispatch of `sprint_generation_started`, `sprint_generation_artifact_created`, `sprint_generation_card_created`, `sprint_generation_quota_exceeded`, `sprint_generation_completed` events.
  - **Persistence** (`mods/persistence/index.ts`): CRUD for sprint generation runs and generated sprint cards with dependency injection (`persistenceDeps.db`).
- **Tests**: 7 test suites with 46 total test cases covering tierPolicy resolution, quota enforcement, readRequirements, generateArtifacts, createSprintCards, and API handler flows (201, 404, 401, 403, feature-flag gate).
