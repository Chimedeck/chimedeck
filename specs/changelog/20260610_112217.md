# CardChat BA Persona Refinement Loop (Iteration 3)

## Update

### AI Provider Integration (`server/extensions/cardChat/mods/provider/index.ts`)
- Reuses `getAssistProviderConfig()` from `board/mods/chat/providerConfig.ts` — no new env vars needed
- 120-second request timeout via `AbortSignal.timeout`
- Structured error handling for auth (401), rate-limit (429), timeout, and unreachable errors
- Provider-agnostic `CardChatProviderMessage` input/output types

### BA Persona Prompts (`server/extensions/cardChat/mods/baPersona/index.ts`)
- System prompt defining the Business Analyst persona: user-focused, requirements-driven, EARS methodology
- 4 question categories: BUSINESS_VALUE, EARS_REQUIREMENTS, ACCEPTANCE_CRITERIA, CONSTRAINTS
- Category detection via signal regex matching on existing messages
- Round-robin question selection ensuring all categories are covered
- Structured question templates per category

### Goal Loop Engine (`server/extensions/cardChat/mods/baPersona/goalLoop.ts`)
- Multi-turn refinement orchestrator with max 8 turns
- Each turn: detect covered categories → select next weakest → build question → call LLM → persist → score → emit activity events → check threshold
- Transitions session to `READY_FOR_REVIEW` when quality score reaches `QUALITY_THRESHOLD` (90)
- Surfaces weakest category for follow-up questions when below threshold

### Deterministic Quality Scoring (`server/extensions/cardChat/mods/qualityScore/index.ts`)
- 4 scoring dimensions at 0–25 each: EARS coverage, acceptance criteria quality, constraint clarity, testability
- Ambiguity penalty (max 10) applied only to assistant output, not user content
- Total score clamped to 0–100
- `QUALITY_THRESHOLD = 90` — below this triggers another refinement round

### Activity Events (`server/extensions/cardChat/mods/activities/index.ts`)
- Fire-and-forget event emission via central `dispatchEvent`
- 4 event types: `card_ai_assist_started`, `card_ai_question_asked`, `card_ai_quality_scored`, `card_ai_assist_ready_for_review`
- Card-scoped events (`boardId: null`)

### Refine API Endpoint (`server/extensions/cardChat/api/refine/index.ts`)
- `POST /api/v1/cards/:cardId/chat/refine` — triggers the goal loop
- Auth: requires valid user token, workspace membership via `ensureWorkspaceMembership`
- Validates session exists and is active before running loop

## Technical Debt

- Server-side tests in jsdom cannot access `Bun.env` because the `db` module import evaluates `config/env.ts`. Both test suites use `vi.mock('../../../../../common/db', ...)` with a Knex-compatible callable mock (`vi.fn(() => mockQueryBuilder)`) and dynamic `await import()` for the tested modules.
- The Knex mock pattern (getter-based chainable object) is verbose but reusable; consider extracting to a test helper at `server/common/__test_utils__/`.
