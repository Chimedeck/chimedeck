# Changelog — 20260612_000000

## Update

### Plugin SDK: CTX_* 1-second caching (`jh-instance.ts`)
- Added a 1-second TTL cache for `t.card()`, `t.list()`, `t.board()`, and `t.member()` context reads.
- Cache key includes the resource ID and requested fields — identical requests within 1 second return the cached value without a postMessage round-trip.
- WHY: on boards with many cards, every `card-badges` handler calls `t.list('id','name')` which sends a `CTX_LIST` postMessage. Caching eliminates redundant round-trips for identical requests.

### Plugin SDK: DATA_GET batching (`jh-instance.ts`)
- `t.get()` now enqueues individual DATA_GET requests into a batch queue instead of sending them immediately.
- The queue flushes every 1 second, sending all accumulated requests as a single `DATA_GET_BATCH` message to the host.
- A 1-second result cache (`dataGetCache`) prevents re-enqueuing identical requests that were already resolved.
- `t.set()` invalidates the cache for the corresponding key so subsequent reads fetch fresh data.
- WHY: on boards with many cards, each card's capability handler issues 4+ DATA_GET calls. Without batching, that's 4N HTTP requests to the server. With batching, all requests across all cards are collapsed into ONE server round-trip per 1-second window.

### Host bridge: DATA_GET_BATCH handler (`usePluginBridge.ts`)
- Added `handleDataGetBatch` that proxies batched DATA_GET requests to the new server batch endpoint (`POST /api/v1/plugins/data/batch`).
- Added `DATA_GET_BATCH` case in the message listener switch statement.
- Added `handleDataGetBatch` to the useEffect dependency array.

## New

### Server: batch plugin data endpoint (`server/extensions/plugins/api/plugin-data/batch.ts`)
- `POST /api/v1/plugins/data/batch` — reads multiple plugin-scoped key/value entries in a single request.
- Accepts `{ items: Array<{ subId, scope, key, visibility, resourceId, boardId, userId? }> }`.
- Returns `{ data: Array<{ subId, value, error? }> }` keyed by subId.
- Validates all items upfront, resolves canonical resource IDs in parallel, then executes a single batched SQL query using OR clauses.
- Registered in the plugin API router (`server/extensions/plugins/api/index.ts`).

## What Should Be Done Next

- Consider adding a similar batching mechanism for `DATA_SET` if plugins frequently write multiple keys in rapid succession.
- Monitor the 1-second batch window — if cards render slowly, the window could be reduced to 500ms or made configurable.
- The CTX cache could be extended to also cache `t.card()` results (currently only `t.list()` is the primary consumer in the escrow plugin).
