## Update

- **Added IDLE to session state machine (`card_chat_sessions.status` CHECK constraint).** Migration `0122_card_chat_idle_state.ts` adds `'IDLE'` to the constraint via raw SQL drop+recreate. `CardChatSessionStatus` type union updated to include `'IDLE'`. `findActiveSession` now matches IDLE sessions so they are findable by resume.
- **Added `POST /api/v1/cards/:cardId/chat/session/resume` endpoint.** New handler (`api/session/resume.ts`) follows the pause handler pattern: auth → membership → body validation → `resumeSession` lifecycle mod → fire-and-forget activity emission. Route registered in the card-chat API router between pause and refine.
- **Added `resumeSession` lifecycle function.** Validates IDLE→ACTIVE_REFINEMENT and PAUSED→ACTIVE_REFINEMENT transitions. Returns 200 no-op for already-active sessions, 409 for READY_FOR_REVIEW (terminal), 404 for not found. `ALLOWED_TRANSITIONS` map updated to include IDLE.
- **Added `ResumeSessionInput` type** to `cardChat/types.ts` (sessionId, cardId, userId).
- **Client `RefinementStatusBadge` maps IDLE→DRAFT** explicitly (same visual as the null/no-session fallback, but now correctly labelled).
