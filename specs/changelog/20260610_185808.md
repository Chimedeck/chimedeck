# Sprint 172 — Workflow Phase Metadata on Columns

## Update

### Server Types (`server/extensions/stateTransitions/common/types.ts`)
- Added `WorkflowPhase` type (6 enum values: NEW_DRAFT, REFINED_PENDING_REVIEW, SYNC_DOCUMENT, READY_FOR_DEV, GENERATE_SPRINT, UPDATE_AS_BUILT)
- Added `PhaseConfig` interface (serviceTierOverride, autoRun, requiresHumanApproval)
- Extended `StateTransitionNode` with optional `workflowPhases?: WorkflowPhase[]` and `phaseConfig?: PhaseConfig`

### Phase Constants (`server/extensions/stateTransitions/common/config/workflowPhases.ts`)
- New config module exporting `VALID_WORKFLOW_PHASES` array and `WORKFLOW_PHASE_LABELS` display-name map

### Validator (`server/extensions/stateTransitions/common/validator.ts`)
- Added `validateNodePhases` function — rejects unknown phase values, duplicate phases, malformed phaseConfig
- Integrated phase validation into `validateGraphShape` loop — absent phases accepted (backward-compatible)

### Serializer (`server/extensions/stateTransitions/common/serializer.ts`)
- `serializeGraph` now preserves `workflowPhases` and `phaseConfig` on nodes when present
- No change to `createDefaultGraphFromLists` — new nodes start without phase metadata

### Phase Resolver (`server/extensions/stateTransitions/mods/phaseResolver/index.ts`)
- `resolveColumnWorkflowPhases({ boardId, listId })` — returns phases for a column, empty array if none
- `resolvePhaseConfig({ boardId, listId, phase? })` — returns phase config with defaults
- 60-second TTL cache with invalidation via `invalidatePhaseCacheForBoard` / `invalidatePhaseCacheFromStateTransitionEvent`

### Client Types (`src/extensions/StateTransitions/api.ts`)
- Added `WorkflowPhase` type and `PhaseConfig` interface to client API types
- Extended `StateTransitionNode` with optional `workflowPhases` and `phaseConfig`

### Column Node (`src/extensions/StateTransitions/components/GraphEditor/ColumnNode.tsx`)
- Renders `PhaseChip` components below label when `data.workflowPhases` is non-empty

### Phase Chip (`src/extensions/StateTransitions/components/PhaseChip.tsx`)
- Coloured pill component with distinct colour per phase (blue/amber/green/purple/orange/teal)

### Column Phase Editor (`src/extensions/StateTransitions/components/ColumnPhaseEditor.tsx`)
- Multi-select checkbox control for all 6 workflow phases
- Toggle switches for autoRun and requiresHumanApproval
- Immediate-on-change propagation (no save button needed)

## Technical Debt

- `ColumnPhaseEditor` is created but not yet wired into the column node edit panel — the graph editor's existing column edit flow (double-click or selection) does not have a dedicated edit panel for column metadata. The editor component is ready for integration when the edit panel is extended.
- Phase cache invalidation is not yet wired to the WS broadcast handler in `common/ws.ts` — this should be done when the trigger engine (Sprint 173) calls the phase resolver at card-move time.
- No DB migration needed — the graph is stored as JSONB; new optional node fields are accepted without schema changes.
