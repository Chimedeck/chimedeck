## Update
- Board chat now supports routing embedding + assist calls through Ollama's hosted OpenAI-compatible API (`https://ollama.com/v1`) via a new `CHAT_PROVIDER=ollama` selector. No call-site changes — the existing OpenAI path is the default and continues to work unchanged.
- New env vars: `CHAT_PROVIDER`, `OLLAMA_API_KEY`, `OLLAMA_BASE_URL` (default `https://ollama.com/v1`), `OLLAMA_EMBEDDING_MODEL`, `OLLAMA_EMBEDDING_DIMENSIONS` (default `1024`), `OLLAMA_ASSIST_MODEL`. All OLLAMA_* values are read directly; no JSON config required.

## New
- Added `server/extensions/board/mods/chat/providerConfig.ts` — single source of truth that resolves the active chat provider (OpenAI vs Ollama) for the embedding and assist paths. Exposes `getEmbeddingProviderConfig()` and `getAssistProviderConfig()`, both of which throw with the same domain-specific error names the call sites already surface (`chat-embedding-provider-not-configured`, `assist-provider-not-configured`).
- Added `server/extensions/board/mods/chat/__tests__/providerConfig.test.ts` — 13 tests covering the openai/ollama branches, base-URL trailing-slash normalisation, provider fallback for unknown `CHAT_PROVIDER` values, and the "ollama ignores CHAT_*" guarantee.

## Technical Debt
- The `BoardChatEmbedding` row now stores `provider: 'openai' | 'ollama'` instead of the previous hard-coded `'http'`. Existing rows that were persisted as `'http'` are still readable; no migration needed.
- The pre-existing `exactOptionalPropertyTypes` errors in `assist/provider.ts` (lines 226/230) are unchanged by this work.
- `getEmbeddingProviderConfig` and `getAssistProviderConfig` always read env at call time (no caching) so the env-mock pattern used elsewhere in the test suite keeps working without re-imports.

## What Should Be Done Next
- Surface the active provider in `/api/v1/flags` (e.g. `chatProvider: 'openai' | 'ollama'`) so admin tooling can show which backend the deployment is using.
- Consider adding per-provider retry/quota semantics in the assist path (Ollama's rate-limit headers differ from OpenAI's).
- Investigate whether Ollama's embedding endpoint always returns the configured dimension — current code falls back to the response length, which is what we want, but worth a defensive test once we have a live Ollama env in CI.
