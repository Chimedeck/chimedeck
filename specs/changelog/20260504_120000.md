# Update
- Changed workspace member add flow to promote existing `GUEST` memberships instead of returning `409 already-a-member`.
- Promotion now updates `memberships.role` to the requested workspace role in a transaction.

# New
- Added workspace-wide role synchronization for promoted guests:
  - Upserts `board_members` for every board in the workspace.
  - Maps workspace roles to board roles as follows:
    - `OWNER` / `ADMIN` -> `ADMIN`
    - `MEMBER` / `VIEWER` -> `MEMBER`
- Added cleanup for legacy guest grants by deleting `board_guest_access` rows for the promoted user within the workspace.

# Technical Debt
- `board_members` only supports `ADMIN` and `MEMBER`, so `VIEWER` must be mapped to `MEMBER`. If strict board-level viewer semantics are required later, a dedicated board viewer role should be introduced.

# What Should Be Done Next
- Add API tests covering promotion from `GUEST` to each workspace role and verify board-wide role sync.
- Add regression tests for mixed state users (existing `board_members` + `board_guest_access`) to confirm deterministic final access model.
