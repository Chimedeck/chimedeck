## New
- **mods/pathGuard/index.ts** — validates file paths against allowed roots (`specs/request_changelog/`, `specs/sprints/`, `specs/architecture/`, `specs/security/`), normalises paths, blocks traversal attempts (`../`, `..\\`)
- **mods/fileCreator/index.ts** — idempotent markdown file creation with YAML front-matter; skips if file already exists at target path
- **mods/fileEditor/index.ts** — applies search/replace edits to existing files; preserves front-matter via pre/post validation; rejects edits that corrupt or remove front-matter
- **mods/fileEditor/frontMatterGuard.ts** — YAML front-matter parser with schema validation for known doc types (request_changelog, sprint, architecture, security); required-field checking
- **mods/committer/index.ts** — git commit with run-scoped staging (only files listed in file scope plan), standard commit message template, `git push` via Bun.spawnSync
- **mods/resume/index.ts** — resumes failed run from last successful step; finds highest completed step by ordering, skips re-executing completed steps, resets attempt counter for the retry step
- **mods/orchestrator/index.ts** — 5-step execution pipeline: REQUESTED → context_gather → file_scope_plan → files_create → files_edit → commit; advances state machine at each transition, handles per-step retry (up to MAX_RETRY_ATTEMPTS=3), emits activity events for each step completion
- **api/approve/index.ts** — POST `.../:runId/approve`: authenticates, validates run is at FILE_SCOPE_PLANNED, returns 200 with APPROVED status; guards against already-approved and already-rejected runs
- **api/reject/index.ts** — POST `.../:runId/reject`: authenticates, requires reason in body, transitions run to FAILED with error_message persisted, returns 200 with REJECTED status
