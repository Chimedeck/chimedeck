# Changelog - 2026-05-08 15:07:42

## Update
- Added a top-right read-state control button on each notification group card in the notifications panel.
- Group button now supports both actions:
  - mark whole group as read (applies to unread entries in the group)
  - mark whole group as unread (applies to read entries in the group)

## New
- Added server endpoint `PATCH /api/v1/notifications/:id/unread`.
- Router now supports `PATCH /api/v1/notifications/:id/read|unread` state actions.
- Added local reducer action `setNotificationReadState` for explicit read flag updates in the notification slice.

## Technical Debt
- Group "mark unread" currently updates client state directly for grouped rows, while per-item "mark read" uses async thunk/API path. This is functionally correct in-panel but should be unified through a dedicated unread thunk for consistency.

## What Should Be Done Next
- Add a `markUnreadThunk` wired with strict typing so both read and unread group actions use consistent async flows.
- Add tests for group toggle behavior on mixed stacks (some read, some unread).
