# Changelog — 2026-06-01 (Iteration 6: Conditional Feature Gate Middleware)

## Update
- `server/config/subscription-tiers.ts`: Added `BooleanFeatureKey`, `BooleanFeatures` types and a `features: BooleanFeatures` field to `TierQuotas`. Added `TIER_ORDER` constant for ascending tier iteration. Updated `free`, `pro`, and `enterprise` tier configs with explicit boolean feature maps (free: all false; pro: all except webhooks; enterprise: all true).

## New
- `server/config/feature-gates.ts`: Declarative endpoint→feature gate map. Defines `GateRule` interface (methods, pathPrefix, feature) and `FEATURE_GATES` array covering automations, webhooks, plugins, customFields, apiTokens, and stateTransitions routes.
- `server/common/requestContext.ts`: Workspace ID resolver for middleware. Extracts workspaceId from `/workspaces/:id/…` paths directly, resolves via DB for `/boards/:id/…` and `/cards/:id/…` paths, returns null for user-scoped or global routes.
- `server/middlewares/featureGate.ts`: Feature-gate middleware with `matchGate`, `minimumTierFor`, and `applyFeatureGate`. Returns `402 feature-not-in-plan` with feature, currentTier, requiredTier, and upgradeUrl. Pass-throughs: `SUBSCRIPTIONS_ENABLED=false`, no workspace context, ungated route, or entitled tier.
- `server/config/feature-gates.test.ts`: 8 tests validating gate map structure and coverage.
- `server/middlewares/featureGate.test.ts`: 27 tests covering matchGate path/method matching, minimumTierFor per feature, and SUBSCRIPTION_TIERS boolean feature flags.

## Technical Debt
- Webhooks (`/api/v1/webhooks`) and API tokens (`/api/v1/tokens`) are currently user-scoped/global without workspace context — the gate silently passes them through until these routes are workspace-scoped.
- The `requestContext.ts` DB lookups (board/card → workspace) add latency on gated board/card routes. A request-scoped WeakMap cache can be added once the feature is stable.
