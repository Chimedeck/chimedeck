# Changelog — 20260603_124034

## Update
- `server/extensions/board/api/index.ts`: Added `GET /api/v1/boards/:id/specs/manifest` and `GET /api/v1/boards/:id/specs/files` route dispatchers.
- `server/extensions/board/types.ts`: Added `SpecsManifestEntry`, `SpecsManifest`, `SpecsManifestCacheEntry`, and `SpecsFileResult` types.

## New
- `server/extensions/board/mods/specs/cache.ts`: In-memory cache and in-flight dedup Maps for manifests and file reads (5-minute TTL each).
- `server/extensions/board/mods/specs/resolvePath.ts`: Path normalisation with traversal, absolute-path, and null-byte rejection.
- `server/extensions/board/mods/specs/manifest.ts`: Recursively walks the checked-out repo for non-hidden `.md` files; computes a stable sha256-based ETag over sorted file paths + ref.
- `server/extensions/board/mods/specs/read.ts`: Reads a single file, enforces a 1 MiB size limit, and generates a sha256 ETag from file content.
- `server/extensions/board/mods/specs/index.ts`: Barrel re-export for all specs helper modules.
- `server/extensions/board/api/specs/load.ts`: `handleLoadSpecsManifest` — auth → board access → workspace membership → MEMBER role guard → 422 when no URL configured → manifest-first load with in-flight dedup → ETag/If-None-Match conditional GET.
- `server/extensions/board/api/specs/read.ts`: `handleReadSpecsFile` — same auth chain → path-traversal rejection → manifest-first path validation → size-limit fast path → file-level in-flight dedup → ETag/If-None-Match conditional GET.
- `server/extensions/board/api/specs/index.ts`: Barrel export for load/read handlers.
- `server/extensions/board/api/__tests__/specs.test.ts`: 17 tests covering manifest load, file read, ETag 304 responses, traversal rejection, missing-path 400, size-limit 422, guest 403, unauth 401, missing URL 422, repo download failure 502, and in-flight dedup.

## Technical Debt
- The `resolveSpecsFilePath` guard is a defence-in-depth measure; callers should also validate that the returned path exists in the manifest before reading (the API handlers do this).
- The manifest walk is recursive but single-threaded; for very large repos this could be optimised with `Promise.all` per directory level.
