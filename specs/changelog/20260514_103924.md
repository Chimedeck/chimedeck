## Update
- Fixed CSP/X-Frame-Options conflict that blocked inline txt/pdf preview in the new attachment viewer page.
- Attachment view endpoint (`/api/v1/attachments/:id/view`) now allows same-origin framing so `?raw=1` can be embedded by the direct-view HTML page.

## New
- `applySecurityHeaders` now supports a `frameAncestors` override so routes can safely opt into `frame-ancestors 'self'` while other routes remain `frame-ancestors 'none'`.

## Technical Debt
- Route-level security header policy is now path-aware in `server/index.ts`; if more endpoints need exceptions, consider centralizing policy mapping by route family.

## What Should Be Done Next
- Add integration coverage asserting response headers for:
  - `/api/v1/attachments/:id/view` -> `frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN`
  - non-attachment endpoints -> `frame-ancestors 'none'` + `X-Frame-Options: DENY`
