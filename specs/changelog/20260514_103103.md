## Update
- Updated GET /api/v1/attachments/:id/view to render a dedicated HTML viewer page on direct navigation instead of forcing a file download.
- Added raw/download query handling so the same endpoint can either stream inline content (?raw=1) or force file download (?download=1).
- Added MIME inference fallback from filename extension to improve inline rendering for files whose stored mime_type is missing.

## New
- New server-rendered attachment viewer page for direct access to attachment view links.
- Viewer behavior by file type:
  - image/*: renders inline image
  - video/*: renders inline video player
  - pdf/text/json/xml and other browser-inline-supported formats: renders in iframe
  - unsupported formats: shows filename and a Download button

## Technical Debt
- Inline support detection currently uses MIME heuristics and extension fallback. If additional enterprise formats are required (e.g. office docs with specialized viewers), this should be extended with explicit handlers.
