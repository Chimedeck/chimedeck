# Card description renders in full in view mode

## Update
None.

## New
`tests/e2e/card-description-expansion.spec.ts`: regression spec seeding a 40-line description via
API and asserting the view-mode preview shows the full content (scrollHeight − clientHeight ≤ 2px)
plus the server-visible round-trip. A second card carries a 240-char unbroken URL; the spec asserts
the preview wraps it without horizontal overflow. A third test opens the modal at 390×844 and
asserts the last line becomes visible by scrolling the mobile panel.

## Technical Debt
- Card description in view mode clipped long descriptions to a 192px (`12rem`) window.
  Root cause: `CardDescriptionTiptap.tsx` (and legacy `CardDescription.tsx`) applied
  `maxHeight: 12rem` + `overflow-hidden` with a small "Show more ↓" toggle whenever the description
  exceeded 400 chars, hiding ~80% of long descriptions and forcing users into edit mode to read them
  (report 2026-10-02: only ~6-8 lines visible). Removed the clamp, gradient overlay, threshold, and
  toggle from both components; view mode now renders the whole description (the card modal content
  column scrolls for very long content). Verified: 784px clipped → 0px, e2e spec red → green ×2.
  Review hardening included: `break-words`/link `break-all` wrapping on the Tiptap preview (long
  unbroken tokens no longer overflow horizontally) and a scrollable `ResizablePanels` mobile branch
  so the full description is reachable on mobile.
- `tests/e2e/_helpers.ts` `registerAndLogin` fixed: the helper now reads `accessToken` from the
  201 register response (register returns it directly), keeping `/auth/token` (10/IP/min limiter)
  reserved for intentional UI login tests.
- An earlier version of this fix went directly to `stable` (PR #336) against branch policy — PRs
  must target `main`; `stable` is promoted only after human inspection of the `main` PR. #338
  restores the correct flow: fix lands on `main` here; `stable` already carries the identical
  change and receives it canonically via promotion, not a duplicate forward PR.
- Pre-existing `tsc --noEmit` errors remain in `CardDescriptionTiptap.tsx` (e.g. `separator`
  null-safety); untouched in this change and present on the base revision.

## What Should Be Done Next
Promote `main` to `stable` through the normal human-inspected promotion flow (this PR's fix is
already on `stable` from #336, so promotion converges the branches; no separate forward PR).
